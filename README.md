# TradingAgents — мультиагентная платформа для дэйтрейдинга

Профессиональный веб-интерфейс + backend для дэйтрейдинга криптовалют:

* **Стратегии** — создание, настройка и разбор стратегий (лонг и шорт).
* **Бэктесты** — прогон любой стратегии на исторических свечах с метриками,
  equity-кривой и таблицей сделок.
* **Live-сигналы** — мультиагентный анализ (5 AI-моделей) и выдача сигналов
  в реальном времени с отслеживанием TP/SL и времени удержания.

Стек: **Python / FastAPI** (backend) + **vanilla HTML/CSS/JS** (frontend) +
**Bybit v5 REST** (публичные данные). Работает «из коробки» в DEMO-режиме
(синтетические данные + детерминированные ответы моделей), а при подключении
ключей переключается на реальный рынок и реальные LLM.

**Поток данных:**

```
Bybit (или синтетика) → MarketData (OHLCV)
        ↓
Strategy.generate() → сигнал индикаторной стратегии (LONG/SHORT/NEUTRAL)
        ↓
5 AI-агентов (стратег, моментум, контрариан, макро, риск) — параллельно
        ↓
Консенсус (взвешенный) → финальный сигнал BUY/SELL/WAIT
        ↓
Live-движок: журнал, TP/SL/время, лимит 30 сделок/день
        ↓
WebSocket → фронтенд (дашборд, live-панель)
```

## 2. Быстрый старт

### Вариант A — локально (рекомендуется для разработки)

```bash
cd TradingAgents

# 1) Виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 2) Зависимости
pip install -r backend/requirements.txt

# 3) (Опционально) ключи — скопируйте и заполните
cp .env.example .env

# 4) Запуск backend (обслуживает и API, и фронтенд)
cd backend
python main.py
```

Откройте **http://localhost:3001** — там сразу и интерфейс, и API.

Без ключей система стартует в **DEMO-режиме**: генерируются реалистичные
синтетические свечи, модели отвечают детерминированно, все функции (сканер,
бэктест, сигналы) работают.

### Вариант B — Docker

```bash
cp .env.example .env   # заполните ключи
docker compose up --build
```

* Фронтенд (nginx): **http://localhost:8080**
* Backend API: **http://localhost:3001** (Swagger: `/docs`)

## 3. Подключение ваших AI-моделей

У вас есть доступ к 5 моделям. Каждая закреплена за своей **ролью** в системе:

| Роль | Что делает | Модель (env-переменная) |
|---|---|---|
| 🧠 Ведущий стратег | план, синтез мнений | `STRATEGIST_MODEL=openai/gpt-6-astra` |
| ⚡ Аналитик моментума | точки входа, импульс | `MOMENTUM_MODEL=openai/gpt-5.6-sol` |
| 🦅 Контрариан | адвокат дьявола, ложные пробои | `CONTRARIAN_MODEL=x-ai/grok-4.5` |
| 💎 Макро | рыночный фон, ликвидность | `MACRO_MODEL=google/gemini-2.5-pro` |
| 🛡️ Риск-менеджер | финальный арбитр RR/стопа | `RISK_MODEL=anthropic/claude-fable-5` |

Самый простой путь — **один ключ OpenRouter** (единая точка доступа ко всем
моделям). В `.env`:

```env
AI_API_KEY=sk-or-v1-XXXX
AI_BASE_URL=https://openrouter.ai/api/v1
```

Ключ `AI_API_KEY` автоматически подставляется для всех 5 ролей. Если какая-то
модель живёт у другого провайдера — задайте для роли отдельные
`*_API_KEY` / `*_BASE_URL` (см. `.env.example`).

**Поддерживаемые провайдеры** (см. `backend/llm/client.py`):

* OpenAI-совместимый протокол `/chat/completions` — OpenRouter, OpenAI,
  xAI (Grok), Google Gemini (совместимый endpoint) и др.
* Native Anthropic Messages API — модели с префиксом `anthropic/`
  (claude-fable-5 подключается именно так).

Проверка: после запуска с ключами на вкладке **Настройки** бейдж сменится с
`DEMO` на `LIVE`, а в журнале агентов появятся реальные ответы моделей.

## 4. Торговые правила (уже реализованы)

Правила из вашего ТЗ заданы в `config.py` / `.env` и **принудительно
соблюдаются** на уровне движка:

| Правило | Значение | Где проверяется |
|---|---|---|
| Максимум сделок в день | **30** (`MAX_TRADES_PER_DAY`) | live-движок, счётчик за сутки |
| Минимальный Take-Profit | **2%** движения цены (`MIN_TP_PCT`) | `Strategy` (не даст TP < 2%) |
| Максимум удержания сделки | **4 часа** (`MAX_HOLD_HOURS`) | бэктест + live (выход по времени) |
| Stop-Loss | 1% (`DEFAULT_SL_PCT`) — RR ≈ 1:2 к цели | сигнал |
| Направление | и лонг, и шорт (`ALLOW_LONG/SHORT`) | консенсус |
| Порог уверенности | 0.55 (`MIN_CONFIDENCE`) | финальный фильтр сигнала |
| Комиссия | 0.055%/сторона (`TRADING_FEE_PCT`) | бэктест |
| Размер позиции | 10% капитала (`POSITION_SIZE_PCT`) | equity в бэктесте |

## 5. Стратегии

### Встроенные (5 штук, лонг и шорт)

| type | Название | Логика |
|---|---|---|
| `momentum_breakout` | Momentum Breakout | пробой N-барового диапазона + фильтр RSI/объёма |
| `rsi_reversal` | RSI Reversal | выход из перепроданности/перекупленности |
| `ema_crossover` | EMA Crossover | пересечение быстрой/медленной EMA |
| `bollinger_breakout` | Bollinger Bands | пробой или возврат полос Боллинджера |
| `vwap_pullback` | VWAP Pullback | откат к VWAP в сторону тренда |

### Как добавить свою стратегию

1. Создайте класс в `backend/strategies/builtin.py` (или отдельном файле):

```python
class MyStrategy(Strategy):
    type = "my_strategy"
    name = "My Strategy"
    description = "Описание"
    default_params = {"period": 14}

    def generate(self, candles, index):
        # только данные ≤ index (без look-ahead!)
        if index < self.params["period"] + 1:
            return self._build_signal(SignalSide.NEUTRAL, candles, index, 0, "нет данных")
        # ... ваша логика ...
        return self._build_signal(SignalSide.LONG, candles, index, 0.6, "причина")
```

2. Добавьте класс в словарь:

```python
BUILTIN_STRATEGIES = {cls.type: cls for cls in (...)}
```

3. Всё — стратегия автоматически появится в UI, будет доступна для бэктеста
   и для мультиагентного анализа. `_build_signal` сам рассчитает TP/SL по
   правилам (TP ≥ 2%, SL задан).

## 6. Бэктест

`POST /api/backtest` (и вкладка «Бэктест» в UI):

* прогоняет стратегию по свечам (без look-ahead — сигнал на баре `i` использует
  только свечи `≤ i`);
* один вход на сделку, выход по **TP / SL / времени** (что раньше);
* учитывает комиссию на вход и выход;
* считает: число сделок, win rate, суммарный PnL, profit factor, max drawdown,
  средние профит/убыток, среднее удержание, Sharpe;
* строит equity-кривую и таблицу сделок.

Пример:

```bash
curl -X POST http://localhost:3001/api/backtest \
  -H 'Content-Type: application/json' \
  -d '{"symbol":"BTCUSDT","strategy":"momentum_breakout","timeframe":"5m","limit":500,
       "tp_pct":2.0,"sl_pct":1.0,"max_hold_hours":4}'
```

> **Важно про реализм:** стратегия не обязана быть «прибыльной на демо-данных».
> Цель платформы — дать инструмент честной проверки. Внутри дня (такие цели TP=2%,
> сделки до 4ч) критично учитывать комиссию и проскальзывание — они уже заложены
> в бэктест. Реальные результаты зависят от выбранного рынка и параметров.

## 7. Мультиагентный анализ и live-сигналы

### Консенсус

5 агентов получают компактный «снимок» рынка (цена, RSI, ATR, объём, последние
свечи + сигнал индикаторной стратегии) и возвращают строгий JSON-вердикт:

```json
{"side": "LONG", "confidence": 0.7, "reason": "...",
 "risks": ["..."], "key_levels": {"support": 150, "resistance": 160}}
```

Оркестратор складывает вердикты с весами ролей (`strategist=1.2, momentum=1.2,
contrarian=0.8, macro=0.6, risk=1.5` + вес индикаторного сигнала) и вычисляет
**сторону и уверенность консенсуса**. Сигнал выдаётся, если уверенность ≥ порога
и сторона ≠ NEUTRAL.

### Live-движок

* каждые `SCAN_INTERVAL_SECONDS` (30с) сканирует все символы параллельно;
* новые сигналы (с дедупликацией по символу/стороне) попадают в журнал и
  рассылаются по WebSocket;
* активные сигналы отслеживаются: закрытие по TP / SL / истечению 4 часов
  (paper-трейдинг, результат фиксируется);
* ведётся счётчик сделок за день (лимит 30).

Это **сигналы**, а не реальные ордера на бирже. Реальное исполнение — следующий
шаг (см. раздел «Куда развивать»).

## 9. Куда развивать платформу (roadmap)

Заготовки/точки расширения уже есть:

1. **Реальное исполнение ордеров** — Bybit Trade API: добавьте подпись запросов
   (`BYBIT_API_KEY/SECRET` уже в конфиге) и метод `place_order` в live-движок.
2. **Real-time данные** — `backend/bybit_websocket.py` содержит готовую обёртку
   подписки на публичный стрим (тикеры/свечи) + `make_cache_updater`.
3. **Персистентность** — сейчас журнал сигналов в памяти; добавьте SQLite/Parquet
   в `data/` (путь уже смонтирован в docker).
4. **Оптимизация параметров** — grid/random search по параметрам стратегий,
   walk-forward-валидация (защита от переобучения).
5. **Больше стратегий и индикаторов** — реестр уже расширяем.
6. **Авторизация, алерты в Telegram, экспорт отчётов.**
7. **Отдельные провайдеры** — в `llm/client.py` легко добавить native-клиентов
   (например, Google Gemini native API).

## 10. Примечание по данным

Если сеть до биржи недоступна (или `DEMO_FALLBACK=true`), `MarketData` генерирует
детерминированные синтетические свечи (геометрическое случайное блуждание с
трендом и циклами) — чтобы вся платформа была функциональна офлайн. Как только
сеть появится, данные автоматически переключаются на реальный Bybit.
