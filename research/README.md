# research/ — исследовательский контур TradeVision

Отдельная папка, которая **не трогает** рабочий портал: она читает его стратегии,
прогоняет их по вашим данным и выдаёт конкретные настройки — что включить, что
заблокировать, какие TP/SL ставить и как отфильтровать сигналы ИИ-моделью.

> Здесь же честно: винрейт и соотношение риск/прибыль (RR) — враги. При RR 2:1
> безубыточный винрейт ≈ 33%, а чтобы держать 75% нужно либо узкий TP против
> широкого SL, либо механизм выхода (breakeven/трейлинг), который превращает
> убытки в нулевые выходы. Поэтому контур всегда показывает винрейт **вместе** с
> экспектанси, profit factor, просадкой и границей Уилсона, а не отдельной цифрой.

## Быстрый старт

```bash
cd /path/to/TradingAgents

# 1) скачать данные (30–40 монет × 6 месяцев × 15m,1h) — см. DOWNLOAD_SPEC.md
python research/run.py download \
  --symbols BTCUSDT,ETHUSDT,SOLUSDT,BNBUSDT,XRPUSDT,DOGEUSDT,... \
  --timeframes 15m,1h --days 180

# 2) проверить качество
python research/run.py quality

# 3) полный прогон: сигналы → перебор TP/SL → фильтры → walk-forward → отчёт
#    (+ зеркальная проверка настоящим движком портала и обучение ИИ-фильтра)
python research/run.py all --mirror

# 4) приёмка найденных настроек
python research/run.py verify
```

Результаты: `research/artifacts/report.md` (для человека),
`recommendation.json` (машинночитаемо), `bundle.json` (ИИ-фильтр для портала).

Проверить механику без биржи и без данных:

```bash
python research/run.py selftest        # синтетика: только проверка кода, не рынка
```

## Команды

| команда | что делает | сколько идёт |
|---|---|---|
| `download` | качает публичные свечи Bybit в `research/data` | 30 монет × 2 ТФ ≈ 10–20 мин |
| `quality` | покрытие, дырки, дубли, битые OHLC по каждому файлу | секунды |
| `extract` | 23 стратегии по каждому бару → кэш сигналов | 40 монет × 15m ≈ 25–40 мин на 8 ядрах |
| `sweep` | перебор вариантов TP/SL/BE/трейлинга по кэшу | минуты |
| `all` | всё выше + фильтры + walk-forward + отчёт + бандл | 1–2 часа на 8 ядрах |
| `all --mirror` | плюс зеркальный прогон движка портала | +20–40 мин |
| `verify` | прогон портала «до» и «после» наших настроек | по числу пар |
| `selftest` | сквозная проверка на синтетике | ~30 c |

Ключи: `--jobs N` (процессы), `--timeframes 15m,1h`, `--strategies ...` (подмножество),
`--tp-min 0.6` (пол по TP), `--winrate-target 75`, `--fee-bps 5.5 --slip-bps 2.0`,
`--grid` (широкая сетка TP×SL), `--mirror`, `--trials N`, `--folds N`.

## Что смотреть в отчёте

1. **§1 Короткий вывод** — что получилось и что нет, без прикрас.
2. **§3 Какие сигналы вообще работают** — по каждой «стратегия/сторона»: сделки,
   винрейт с нижней границей, экспектанси, PF, просадка. Плюсовые идут в настройки,
   минусовые — в стоп-лист.
3. **§4 Перебор TP/SL** — таблица вариантов и безубыточный винрейт для текущих издержек.
4. **§5 Диагностика** — доля сделок, где цена даже не дошла до TP, медианные ходы
   в пользу/против и формула TP ≈ k×ATR%, SL ≈ k×ATR% (переносится между монетами).
5. **§6 Walk-forward** — держится ли результат вне выборки.
6. **§7 Мета-модель** — во сколько раз фильтр поднял винрейт и сколько сделок съел.
7. **§8 Зеркальный прогон** — цифры движка портала (самая честная проверка).

## Включение результатов в портал

```bash
# research/artifacts/recommendation.json → поле env_snippet
grep -n "env_snippet" -A 25 research/artifacts/recommendation.json
```

Строки вида `MANUAL_TP_PCT=...`, `HOURS_BLOCK=...`, `STYPE_BLOCKLIST=...`,
`CURATED_BUNDLE=...` добавляются в `portal/.env`, после чего портал перезапускается.
Первые дни держите `CURATED_SHADOW=true` — фильтр будет считать, но не резать:
видно в `/api/metrics` (`curated.rejected`, `curated.passed`) и в логах.

Подробности — [ARCHITECTURE.md](ARCHITECTURE.md), контракт данных — [DOWNLOAD_SPEC.md](DOWNLOAD_SPEC.md).

## Тесты

```bash
python -m pytest research/tests -q
```

Проверяют главное: признаки считаются одинаково в исследовании и в портале,
нет взгляда в будущее, барьеры разрешаются консервативно, бандл мета-модели
читается порталом теми же числами.
