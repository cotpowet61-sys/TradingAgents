# Архитектура исследовательского контура

Задача контура: ответить на вопрос **«какие из 23 стратегий портала реально
приносят деньги, при каких TP/SL и в каком контексте»** — и не соврать при этом.

```
research/data/*.csv            ← ваши выгрузки (см. DOWNLOAD_SPEC.md)
        │
        │  tvresearch/data.py      контроль качества: дырки, дубли, битые OHLC
        ▼
   extract_signals (тяжёлый шаг, кэшируется)      tvresearch/signals.py
        │  23 стратегии портала × каждый бар × все монеты/ТФ
        │  на выходе — поток сигналов: бар, сторона, conf, признаки, ATR%
        ▼
   artifacts/signals/*.csv.gz
        │
        │  resolve_trades + barriers.py
        │  вход по ОТКРЫТИЮ следующего бара, стоп/цель/таймаут,
        │  комиссия + проскальзывание, консервативный intrabar
        ▼
   сделки для каждого варианта выхода (TP/SL/BE/трейлинг)
        │
        ├─ search.py     перебор вариантов, поиск фильтров, walk-forward,
        │                диагностика «почему цель не берётся»
        ├─ curated.py    мета-модель (ИИ-фильтр) → bundle.json для портала
        ▼
   artifacts/report.md  +  artifacts/recommendation.json  +  bundle.json
        │
        │  строки .env и CURATED_BUNDLE
        ▼
   portal/   (сканирует рынок, применяет фильтры и мета-модель)
```

## Три уровня достоверности

| уровень | модуль | что честно обещает |
|---|---|---|
| A. сигналы | `signals.extract_signals` | сигнал виден только по закрытому бару; никаких будущих свечей |
| B. перебор | `barriers.py` + `search.py` | вход по open следующего бара, издержки вычтены, при конфликте TP/SL в баре — стоп |
| C. приёмка | `engine.mirror_run` | прогон **настоящего** движка портала (`signal_backtest._simulate`) на тех же CSV |

Уровни A и B нужны, чтобы перебрать тысячи комбинаций за минуты. Уровень C —
чтобы не спорить: он запускает тот же код, который работает в сканере портала
(авто-подбор стратегии, `signal_gates`, кулдаун 30 минут, одна сделка на пару,
breakeven/трейлинг). Если результат уровня B не подтверждается уровнем C —
верить нужно уровню C.

## Почему это не «подгонка под историю»

1. **Train/test разбиты по времени.** Параметры подбираются на первых 70% сделок,
   а цифры, которые показываются в отчёте, считаются на последних 30%.
2. **Walk-forward.** Правила отбираются на обучающем окне и проверяются на
   следующем, ещё не просмотренном. В отчёте видно каждый фолд.
3. **Множественная проверка.** Винрейт сопровождается нижней границей интервала
   Уилсона: мало сделок → широкая граница → вариант не проходит.
4. **Экономика прежде винрейта.** Целевая функция — экспектанси после издержек.
   Винрейт — только ограничение. Это защищает от «75% на маленьких TP и огромных SL».
5. **Пол по TP.** `--tp-min` (по умолчанию 0.6%) не даёт накрутить винрейт
   микроскопическими целями, которые не переживут комиссию и проскальзывание.
6. **Синтетика помечается.** Прогон на сгенерированных данных (`run.py selftest`)
   подписан в отчёте как нерепрезентативный: он проверяет механику, а не рынок.

## Мета-модель: как ИИ совмещает сигналы со стратегиями

Признаки (19 штук, `features.py`) — только из прошлого: уверенность стратегии,
ATR%, RSI, растянутость от EMA21, наклон EMA, объём и сезонный объём, ширина
полос Боллинджера, положение в 20-барном канале, расстояние до минимума/максимума,
тренд EMA21/EMA55, час и день недели (циклически), сторона сигнала, плановый RR.

Модель: логистическая регрессия (вероятность прибыльной сделки) + ридж-регрессия
(ожидаемый PnL). Пороги `threshold_win` / `threshold_pnl` подбираются на train так,
чтобы выполнялся целевой винрейт при максимальном сохранении сделок. Если цель
на train недостижима, в бандл и отчёт честно пишется `target_met: false`.

Никаких «тяжёлых» библиотек: арифметика — умножение матрицы на вектор и сигмоида.
Портал применяет бандл модулем `portal/curated.py`. Признаки считаются **тем же
алгоритмом** — равенство проверяется тестом
`research/tests/test_research.py::test_features_match_portal_exactly`.

## Что именно инвертируется в портал

| выход контура | переменная портала | смысл |
|---|---|---|
| TP/SL из перебора | `MANUAL_TP_PCT`, `MANUAL_SL_PCT` | конкретные цели в процентах |
| breakeven/трейлинг | `BE_TRIGGER_PCT`, `BE_OFFSET_PCT`, `TRAIL_START_PCT`, `TRAIL_PCT` | механизм, который честно повышает винрейт |
| фильтры входа | `STYPE_BLOCKLIST`, `HOURS_BLOCK`, `ATR_PCT_BLOCK`, `VOL_SEASON_BLOCK`, `MIN_CONFIDENCE` | те же поля, что читает `signal_gates.entry_block_reason` |
| список стратегий | блок комментариев + `STYPE_BLOCKLIST` | разрешённые пары «стратегия/сторона» |
| мета-модель | `USE_CURATED`, `CURATED_BUNDLE`, `CURATED_SHADOW` | ИИ-фильтр сигналов |

Порядок безопасного включения: сначала `CURATED_SHADOW=true` (фильтр считает, но
ничего не блокирует — смотрим в `/api/metrics` и логах), через несколько дней —
`false`, то есть фильтр начинает реально резать сигналы.

## Границы применимости (то, чего контур не делает)

- не гарантирует будущую доходность: рынок меняется, 6 месяцев истории — не вечность;
- не заменяет юридическую проверку и не является инвестиционной рекомендацией;
- не торгует сам: он даёт настройки и фильтр, решения остаются за вами;
- не отменяет проскальзывание на тонких монетах: модель издержек здесь
  фиксированная (тейкер + N б.п.), реальный проскальзывание на новостях может быть хуже.

## Как расширять

- добавить свою стратегию: положить класс в `backend/strategies/builtin.py` —
  контур подхватит её автоматически (`all_strategy_types()`);
- добавить признак: `features.py::FEATURE_NAMES` **и** `portal/curated.py::FEATURE_NAMES`
  (оба списка обязаны совпадать, тест это проверяет), затем переобучить бандл;
- сменить модель: `curated.py::train_bundle` — формат бандла остаётся JSON,
  портал читает `model_win` / `model_pnl`; при смене формул поднимите `BUNDLE_VERSION`
  и добавьте проверку в `portal/curated.py::validate_bundle`.
