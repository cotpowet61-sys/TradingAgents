# Чек-лист боевого запуска TradeVision Portal

Всё, что можно было закрыть кодом, тестами и конфигурацией, — закрыто и проверено
(63 теста портала + 20 тестов исследовательского контура, bandit, pip-audit,
живой прогон сервера). Ниже — что осталось сделать **вам**, по порядку, и как
убедиться, что это сработало.

---

## 1. Юридический минимум (без этого продавать нельзя)

Заполните маркеры `[[...]]` в файлах:

| Файл | Что подставить |
|---|---|
| `portal/static/legal/imprint.html` | правовая форма и имя продавца, адрес, e-mail, Telegram, регистр/VAT, ответственное лицо, заявление о потребительском арбитраже |
| `portal/static/legal/privacy.html` | контролёр, контакт по защите данных, хостинг-провайдер и его локация (DPA), надзорный орган, контакт для сообщений об уязвимостях |
| `portal/static/legal/terms.html` | юрисдикция/применимое право, пункт о праве отзыва для потребителей ЕС, сроки возврата |

Пока маркеры не заполнены, страницы отдаются с красной плашкой «ЧЕРНОВИК» и
заголовком `X-Legal-Draft: 1` — это защита от случайной публикации пустого Impressum.

Проверка: `curl -sI https://ваш-домен/legal/imprint.html | grep X-Legal-Draft`
должно вернуть `x-legal-draft: 0`.

**Дополнительно покажите юристу** (код этого не решает): MiCA/BaFin-контур
продажи аналитики по крипто-деривативам, AML/KYC-риски приёма USDT, налоги.
Это шаблоны-основы, а не юридическая консультация.

## 2. Платежи: кошелёк и живая транзакция

1. Впишите **публичные** адреса приёма в `portal/.env`:
   `WALLET_TRC20=...` (TRON) и/или `WALLET_BEP20=...` (BSC), выставьте
   `TRC20_WATCH_ONLY_ACK=true` (подтверждение контура watch-only).
2. Для BEP20 нужен бесплатный ключ `BSCSCAN_API_KEY` (api.bscscan.com).
3. Проверьте приём **реально**: зарегистрируйтесь, создайте инвойс, отправьте
   ровно указанную сумму (с точностью до центов!) — доступ активируется
   автоматически за 1–2 минуты, в Telegram владельцу придёт уведомление.

> Приватные ключи/seed на сервер не попадают никогда — только публичные адреса.

Проверка: `journalctl -u tradevision | grep billing` → строка «оплата … доступ до …».

## 3. AI-ключи (иначе агенты отвечают демо-вердиктами)

- `AI_API_KEY` + `AI_BASE_URL` (любой OpenAI-совместимый endpoint; по умолчанию justcode.lol).

## 4. Продакшн-деплой

```bash
# ветку указываем явно — основная ветка репозитория может не содержать доработок
BRANCH=arena/526e0286-tradingagents DOMAIN=tv.example.com bash portal/deploy/deploy.sh
```

Скрипт: ufw (22/80/443), fail2ban, unattended-upgrades, пользователь без sudo,
код из указанной ветки в `/srv/tradevision`, venv + `portal/requirements.txt`,
`.env` с сгенерированными `PORTAL_AUTH_SECRET`/`ADMIN_TOKEN`, systemd с hardening,
Caddy с HTTPS, ежедневный бэкап `portal/data` **вместе с `.env`** (ротация 14 дней).

Ветку можно не указывать (`BRANCH` не задан) — тогда скрипт спросит у GitHub, какая
ветка основная, и возьмёт её. **Проверьте, что в ней есть последние доработки:**
если работа велась в отдельной ветке, сначала смержите её в основную на GitHub
(pull request → merge) либо задайте `BRANCH=<нужная-ветка>`.

Что нельзя терять: **`PORTAL_AUTH_SECRET`** — без него ключи клиентов не расшифруются,
а все сессии инвалидируются. Он бэкапится скриптом; храните копию в менеджере секретов.

Обязательные значения в `.env` для боевого режима: `SAAS_MODE=true`,
`SITE_URL=https://ваш-домен`, `TELEGRAM_URL=...`, `ADMIN_TOKEN` (≥16 символов),
`OWNER_EMAILS=ваш@email` (вечный доступ владельцу).

Проверка: `curl -s https://ваш-домен/api/health` → `{"ok":true,...}` и
`GET /api/metrics` с заголовком `x-admin-token`.

## 5. Настройки безопасности в бою (свериться один раз)

| Переменная | Боевое значение | Почему |
|---|---|---|
| `TRUST_PROXY_HEADERS` | `true` **только** за Caddy | иначе IP и rate-limit подделываются заголовком |
| `FRAME_ANCESTORS` | `self` (или `self https://partner.example`) | кто может встраивать портал в iframe |
| `ALLOWED_ORIGINS` | пусто или домены партнёров | доп. Origin'ы для CORS |
| `REQUIRE_REAL_DATA` | `true` | не выдавать сигналы на «учебном графике» |
| `UNSAFE_LOCAL` | `false` | иначе отключается проверка конфигурации |
| `SECURITY_HEADERS` / `CSRF_ORIGIN_CHECK` / `HSTS_ENABLED` | `true` | CSP/анти-CSRF/HSTS |
| `BACKTEST_MAX_*`, `MAX_BODY_MB` | дефолты | анти-DoS на тяжёлые прогоны |

Сервер сам откажется стартовать при `SAAS_MODE=true`, если нет
`PORTAL_AUTH_SECRET`, `ADMIN_TOKEN` или ни одного кошелька приёма (защита от
самоблокировки: включил продажу — а оплатить нечем).

## 6. Что проверить после запуска (первые сутки)

1. **Оплата тестовой суммой** → активация → `journalctl -u tradevision | grep billing`.
2. **Read-only ключи**: подключите в кабинете → должны сохраниться; ключ с правами
   торговли обязан быть **отклонён** с понятным текстом (проверка идёт на бирже).
3. **«Мои сделки»**: загрузка истории до 365 дней; если истории больше, чем
   выкачивается за проход, UI покажет флаг неполной выгрузки.
4. **Сброс пароля**: запрос → ссылка уходит владельцу в Telegram → пароль меняется,
   все прочие сессии вылетают.
5. **Трек-рекорд**: на пустой базе лендинг пишет «collecting data», а не «красивый winrate».
6. **Сканер**: если Bybit недоступен из вашей сети — баннер «сигналы приостановлены»
   и **ноль** записей в трек-рекорде (это ожидаемое, честное поведение; лечится VPN на сервере).

## 8. Исследовательский контур и ИИ-фильтр сигналов (после деплоя)

Порядок, который даёт измеримый результат, а не обещания:

```bash
cd /srv/tradevision                      # каталог с кодом на сервере

# 1) скачать данные: 30–40 монет × 6 месяцев × 15m,1h (публичный API, без ключей)
python research/run.py download --symbols BTCUSDT,ETHUSDT,... --timeframes 15m,1h --days 180

# 2) проверить качество выгрузки (покрытие < 90% → пара отбрасывается)
python research/run.py quality

# 3) полный прогон: все 23 стратегии × все пары, перебор TP/SL/BE/трейлинга,
#    walk-forward, обучение ИИ-фильтра + зеркальная проверка движком портала
python research/run.py all --mirror

# 4) приёмка найденных настроек
python research/run.py verify
```

Что получится: `research/artifacts/report.md` (человекочитаемый разбор),
`recommendation.json` (в нём поле `env_snippet` — строки для `portal/.env`),
`bundle.json` (ИИ-фильтр).

Включение ИИ-фильтра в портале (**безопасный порядок**):

1. добавьте в `portal/.env`:
   `USE_CURATED=true`, `CURATED_BUNDLE=/srv/tradevision/research/artifacts/bundle.json`,
   `CURATED_SHADOW=true` (сначала тень: фильтр считает, но НЕ блокирует);
2. перезапустите: `systemctl restart tradevision`;
3. смотрите `GET /api/metrics` → блок `curated` (`checked`, `shadow_rejected`, `passed`)
   и логи `[curated]`;
4. через несколько дней, убедившись, что фильтр отсекает именно шум, поставьте
   `CURATED_SHADOW=false` — теперь он реально режет сигналы.

Строки TP/SL/фильтров из `env_snippet` вписывайте осознанно: в отчёте рядом с каждым
числом стоит число сделок, нижняя граница винрейта и ожидание на сделку после издержек.
Если в отчёте написано «цель по винрейту 75% не достигнута» — это честный ответ, а не
недоработка: винрейт и соотношение риск/прибыль связаны, и подделывать эту связь
(например, микроскопическим TP) портал не будет.

Разбор сделок прямо в бою (без отдельного прогона): админка `/static/admin.html` →
блок «Разбор сделок с биржи» → «Разобрать сделки» → «Подобрать TP/SL» → «Применить в .env».
Каждое действие пишется в аудит.

## 9. Что осталось за пределами кода (и это нормально)

| Остаток | Почему |
|---|---|
| Живая транзакция USDT на ваш кошелёк | внутри песочницы нет ни вашего кошелька, ни доступа к Tron/BSC |
| Юридическая валидация Impressum/Terms/DSGVO | подпись под документами — только ваша и вашего юриста |
| Возможный переход на Postgres при росте | SQLite хватает до ~10k пользователей; `PORTAL_DATABASE_URL` уже поддерживается кодом |
| Ротация/KMS для `PORTAL_AUTH_SECRET` | бэкап настроен; аппаратная защита ключа — задача вашей инфраструктуры |
