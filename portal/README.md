# TradeVision Portal

Отдельная платформа поверх движка TradingAgents:
AI-совет агентов по графикам Bybit, live-сигналы по вашему watchlist'у
и полный разбор ваших реальных сделок — в неоновом терминальном дизайне.
Умеет работать и как платный SaaS-сервис (подписка, кабинет, оплата USDT).

## Запуск (1 клик)

| Система | Команда |
|---|---|
| Windows | двойной клик по `portal\start.bat` |
| Linux/macOS | `./portal/start.sh` (флаг `--no-broker` выключает наблюдатель за блокчейном) |
| Docker | `docker compose up -d portal` (порт 3005, данные в `./portal/data`) |

Откроется **http://localhost:3005**. Докер не обязателен — поднимается venv
`.venv-portal` рядом с проектом. Порт 3005 независим от 3003/3001.

## Тесты и CI

```bash
./portal/run_tests.sh          # venv + pytest (сеть не нужна: биржа за mock'ами)
```

- `portal/tests/` — pytest-набор: денежный путь (регистрация → инвойс → оплата →
  доступ), гейт SaaS, безопасность (заголовки, CSRF/Origin, лимиты, cookie,
  сброс пароля, аудит, keyvault), честность сканера (синтетика не попадает в
  ленту/обучение/трек), нормализация сделок, пагинация Bybit.
- `.github/workflows/portal-ci.yml` — тесты на Python 3.11/3.12, `bandit`,
  `pip-audit`, проверка «секретов в git нет», синтаксис JS.

## Что умеет

### 📈 Терминал
- График на официальном **Lightweight Charts от TradingView** (библиотека локально,
  без CDN), данные — публичный API Bybit (USDT-перпетуалы, спот как запасной).
- Watchlist с живыми ценами, неоновая вспышка карточки при новом сигнале.
- Кнопка **🤖 Совет агентов**: стратегия подбирается авто-бэктестом под свежий график.

### ⚡ Сигналы
- Live-лента: индикаторная математика, **AI-токены не тратятся** (AI — только по клику).
- Самообучение по исходам: правила block/tighten/boost по (монета × стратегия × сторона)
  с 95% интервалами Уилсона и TTL 72 ч, плюс AI-куратор, который правила чистит.
- **Честность данных**: если биржа недоступна и вместо свечей идёт синтетика
  («учебный график»), сканер **не выдаёт сигналы** и не пишет исходы — иначе
  случайные числа попали бы в обучение и в публичный трек-рекорд.
- Ротация таймфреймов и адаптивный ритм сканирования (`SCAN_CADENCE_SECONDS`),
  чтобы не долбить публичный API на 4 монетах × 7 ТФ.

### 💼 Мои сделки
- Реальная история с Bybit: read-only ключи (проверяются **на бирже**: ключ с
  правами торговли/вывода отклоняется) или CSV-экспорт.
- Статистика, кривая эквити, раскладки, авто-паттерны, «ДНК торговли» (MAE/MFE,
  сессии, RSI-зоны, режимы), «Моя стратегия», AI-разбор.
- Кэш на пользователя, параллельная загрузка окон истории, флаг неполной выгрузки.

### ⚙️ Настройки
- Ключ AI-endpoint + список моделей, тумблеры ролей, watchlist, порог уверенности,
  риск/депозит/плечо, квант-фильтры, breakeven/трейлинг. Всё пишется в `portal/.env`.

## SaaS-режим (продажа подписки)

`SAAS_MODE=true` включает лендинг → регистрацию → оплату USDT (TRC20/BEP20) →
кабинет. Оплата ловится watch-only сканером блокчейна (Tronscan/BscScan) и
матчится по уникальным центам суммы; инвойс идемпотентен по `tx_hash`.

**Перед первым запуском боевого режима сервер сам проверяет конфигурацию**
(`enforce_startup`) и откажется стартовать, если чего-то критичного нет
(пустой `PORTAL_AUTH_SECRET`, нет `ADMIN_TOKEN`, не задан ни один кошелёк).
Это защита от классической самоблокировки: включил SaaS без кошельков — и
доступ к терминалу закрыт, а оплатить нечем. Для локальной отладки есть
`UNSAFE_LOCAL=true` (в бой не ставить).

## Безопасность

Реализовано в коде (и покрыто тестами):

| Область | Что сделано |
|---|---|
| Сессии | cookie HttpOnly + SameSite=Lax + Secure за HTTPS, в БД только sha256 токена, скользящее окно 30 дней, каскадный отзыв |
| Пароли | PBKDF2-HMAC-SHA256, 260k итераций, соль на пользователя, политика сложности, авто-апгрейд стоимости хэша, сброс по одноразовой ссылке (в БД — только хэш токена) |
| CSRF | все небезопасные методы принимаются только с нашего Origin/Host (`CSRF_ORIGIN_CHECK`) |
| Заголовки | CSP, `frame-ancestors`, nosniff, Referrer-Policy, Permissions-Policy, HSTS за HTTPS; `no-store` для API |
| Rate limit | персистентный (таблица `rate_limits`): переживает рестарт и работает при нескольких воркерах, с `Retry-After` |
| Админка | `x-admin-token` ≥16 символов, сравнение за постоянное время, лимит попыток, журнал `audit` |
| Ключи Bybit | только read-only (проверка на бирже при сохранении), AES-256-GCM, ключ из `PORTAL_AUTH_SECRET` (пустой секрет = отказ, а не предсказуемый ключ) |
| Приватные ключи крипты | на сервере не существуют: только публичные адреса приёма |
| Данные | персональные эндпоинты доступны только владельцу своих read-only ключей |
| Изоляция | systemd-hardening (`ProtectSystem=strict`, `CapabilityBoundingSet=`, `SystemCallFilter`), порт наружу — только через Caddy |
| Наблюдаемость | `/api/metrics` (админ/владелец), журнал `audit`, логи ошибок сканера вместо `except: pass` |

Важно про прокси: `TRUST_PROXY_HEADERS=true` допустим **только** когда впереди
Caddy/nginx. Прямое выставление порта в интернет требует `false` — иначе IP и
лимиты подделываются заголовком `X-Forwarded-For`.

## Эксплуатация

```
journalctl -u tradevision -f            # логи портала
journalctl -u tradevision | grep billing# оплаты
GET /api/health                          # состояние + источник данных
GET /api/metrics                         # метрики (x-admin-token или владелец)
```

Деплой на чистый Hetzner Ubuntu 24.04:

```bash
DOMAIN=tv.example.com bash portal/deploy/deploy.sh
```

Скрипт ставит ufw (22/80/443), fail2ban, unattended-upgrades, создаёт
пользователя без sudo, разворачивает стабильную ветку (`BRANCH`, по умолчанию
`main`), генерирует `.env` с секретами, поднимает systemd-сервисы и Caddy,
настраивает ежедневный бэкап `portal/data` **вместе с `.env`** (14 дней).

Что нельзя терять: **`PORTAL_AUTH_SECRET`** — без него ключи клиентов не
расшифруются, а все сессии инвалидируются. Он бэкапится вместе с данными.

## Юридический минимум перед продажами

Шаблоны лежат в `portal/static/legal/` и отдаются по `/legal/imprint.html`,
`/legal/privacy.html`, `/legal/terms.html`. Пока в файлах остались маркеры
`[[...]]`, страница помечается как **черновик** (красная плашка + заголовок
`X-Legal-Draft`). Заполните: правовую форму и адрес продавца, контакт,
юрисдикцию, право отзыва для потребителей, хостинг-провайдера и, при
необходимости, налоговые идентификаторы. Это шаблон-основа, а не юридическая
консультация — перед продажами в ЕС покажите его юристу (DSGVO, MiCA/BaFin,
право отзыва для цифровых услуг, AML-контур крипто-платежей).

## Экономия токенов (по дизайну)

Портал **никогда не вызывает AI сам по себе**: сканер сигналов — чистая
математика по свечам. Модели вызываются только по кнопке; выключенные тумблером
роли не вызываются даже по кнопке.

## Прочее

- Порт независим: **3005** (`PORTAL_PORT` в `portal/.env`).
- Данные и БД: `portal/data` (переопределяется `PORTAL_DATA_DIR`), настройки —
  `portal/.env` (`PORTAL_ENV_FILE`). Оба пути исключены из git.
- Если Bybit недоступен (гео-блок), данные отмечаются бейджем «⚠️ Учебные
  данные», а сигналы и бэктесты **не выдаются** — есть кнопка «🔍 Проверить» в
  Настройках и авто-перебор хостов `api/api2/bytick/bybit.eu`.
